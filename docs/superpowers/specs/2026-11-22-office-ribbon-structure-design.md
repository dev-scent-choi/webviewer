# 리본을 실제 오피스 구조로(워드·엑셀·PPT 전체 탭·묶음·단추) 설계

작성 2026-11-22. 가지 `office-artcraft`. 사용자 지시: "메뉴는 다시 말하지만 워드, 엑셀, ppt등 실제 office의 구조와 디자인으로 추가해야 되는 거야." 리본 스킨 설계(`2026-11-22-artcraft-ribbon-skin-design.md`)의 §2-2 "단추를 더하지 않음·없는 묶음은 만들지 않음"은 **폐기**한다. 모양 규격(제목 24·탭 22·리본 62·상태 18px, 아이콘 32/16px, 한글 이름, 상태 표시 숨김)은 그대로다.

## 1. 요구
1. 세 편집기의 리본은 **Microsoft 365(한국어) 워드·엑셀·파워포인트의 탭·묶음·단추 구조**를 그대로 갖춘다. 탭 이름·순서, 묶음 이름·순서, 묶음 안 단추의 종류·이름·큰/작은 구분·드롭다운 여부까지.
2. 이미 있는 우리 기능은 오피스의 같은 자리에 둔다(id·처리기·단축키 유지). 아직 없는 기능은 **단추는 보이되 비활성**(`disabled`, 말풍선 "준비 중 — <기능 이름>")로 두고, 뒤 단계에서 차례로 구현한다(cadview 의 "준비 중 170개" 방식과 같음).
3. 읽기 전용(ui=view)은 기존 규칙: 쓰는 단추는 `.ro-disabled`. 준비 중 단추는 `disabled` 가 우선.
4. 콘텐츠만 보기(`ui=content`)는 리본 전체 숨김 — 영향 없음.
5. 보기 화면(view.html)은 범위 밖(단일 "보기" 탭 유지).

## 3. 하지 않는 것(이 단계)
- 준비 중 단추의 기능 구현(다음 단계들에서 앱별로 묶어 구현).
- 파일 탭(백스테이지) 항목 확장은 목록만 적고 화면은 기존 것.
- 아이콘 세트 교체: 준비 중 단추는 오피스 의미에 맞는 단색 선 아이콘을 새로 그리되(SVG 인라인, 번들 크기 상한은 계획이 정함), 기존 아이콘은 유지.

## 4. 검사
- 목록 대조 e2e: 계획의 목록 표(JSON 로 함께 커밋)와 실제 DOM 의 탭·묶음·단추가 1:1 로 일치(이름·순서·크기·드롭다운·disabled 여부). 기존 id 전부 존재·동작.
- 기존 e2e 전부 통과(단추 수를 고정 단언한 것은 목록 표 기준으로 갱신 — 사용자 지시에 따른 변경).
- 62px 규격·600px·ui=view 흐림·`verify:ribbon-skin` 그대로.
- 사람이 보는 확인: 세 편집기의 모든 탭을 M365 캡처와 나란히.
