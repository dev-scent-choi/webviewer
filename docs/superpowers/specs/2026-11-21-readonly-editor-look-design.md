# 기본 열기 = 읽기 전용 편집기 화면(편집 도구 보임·비활성화) 설계

작성 2026-11-21. 가지 `office-artcraft`(아트크래프트 옵션 뒤에 이어서). 사용자 요구: "웹 화면에서 열기 할 때는 편집 모드 화면처럼 열리게 하고 편집 도구들은 안 보이게 숨겨줘. (이게 기본임)"

> 2026-11-21 밤 개정: 사용자 결정 "그냥 도구 메뉴는 보이는데 비활성화 시키는걸로 하자. 메뉴들이 다 너무 이상해짐." — 리본을 숨기고 얇은 줄을 두던 첫 안을 버리고, **편집기 화면을 전부 그대로 보이되 문서를 쓰는 조작만 흐리게(비활성화)** 한다. §3.1·§3.3·§4·§6이 바뀌었다.

## 1. 목표

메인 화면(`/`)의 기본 "열기"가 워드·엑셀·PPT 문서를 **편집기의 화면 그대로**(같은 배치·같은 그리기·같은 리본) 보여 주되, **편집 도구는 보이지만 흐리게 꺼져 있고 편집은 되지 않는** 상태로 연다. 지금 있는 읽기 전용 편집기(canEdit=false 토큰)를 바탕으로 하고, 새는 편집 경로를 막는다.

## 2. 지금 상태(코드 확인, 2026-11-21)

- 세 편집기 모두 `canEdit=false` 토큰이면 이미 읽기 전용으로 열린다(edit.ts:101 `readOnly`, room.ts:2853 서버가 Update를 버림, 참석자·커서는 받음). 단 `canDownload=true`여야 편집기 자료 경로(`resolveEditorDataView`)가 열린다(`isViewOnly = !canEdit && !canDownload`).
- 읽기 전용에서도 남아 있는 도구: 워드 — 검토·보기 탭과 리본, 상태 줄; 엑셀 — 보기 탭, 수식 입력줄(읽기 전용), 시트 탭 우클릭 메뉴(삽입·삭제·이름 바꾸기 — 서버는 버리지만 화면이 어긋남), 시트 추가/삭제, 틀 고정이 구조를 직접 씀; PPT — 파일 탭만. 백스테이지(정보·내려받기·인쇄)는 셋 다 남음.
- `canCopy`를 편집기는 지키지 않는다(보기 화면 view.ts:94는 지킴).
- 향기랩은 `editorUrl`만 쓰고(늘 편집 모드), 메인 화면은 `openViewer`가 `viewerUrl`로 간다(2026-09-17에 편집기 경로를 되돌린 이유: Yjs 전체 동기화로 느림, PPT 편집기가 글상자만 그림 — 후자는 품질 작업으로 해소됨: FIX-PPTX 편집 화면 34/34, 그림·표·차트·스마트아트 표시).

## 3. 동작

### 3.1 읽기 전용 "보기 꾸밈"(`ui=view`)
편집기 주소에 `&ui=view`가 붙고 토큰이 `canEdit=false`이면 **보기 꾸밈**으로 연다(둘 중 하나라도 아니면 지금과 같다 — 향기랩·동시편집·주소에 ui=view가 없는 읽기 전용 편집기는 영향 없음).

원칙: **보임·비활성화** — 편집기 틀(리본 탭과 판, 빠른 실행, 파일 화면, 엑셀 수식 입력줄, 상태 줄, 섬네일)은 전부 보인다. 조작마다 하는 일로 가른다: 문서를 쓰는 것은 흐리게(`disabled` + `aria-disabled="true"` + `.ro-disabled` — 불투명도 45 %, 마우스 안 받음, 말풍선 끝에 "읽기 전용"), 보기만 하는 것은 그대로 눌린다. 리본 탭 자체는 눌러서 모든 탭을 둘러볼 수 있다. 세 편집기가 같은 규칙(`officeShell` 한 곳, 허용 목록 `viewStrip.ts viewControlAllowed`).

흐림은 편집기가 나중에 다는 단추(PPT 디자인·전환 갤러리)에도 걸리고(리본 안만 지켜보는 MutationObserver), 편집기가 선택에 따라 `disabled`를 풀어도 다시 꺼진다. 마지막 겹으로 흐린 조작에 닿은 click·mousedown·change·input은 잡기 단계에서 끊는다. 진짜 쓰기 차단은 여전히 서버(canEdit=false → room.ts가 Update를 버림).

### 3.2 토큰과 주소
- `POST /api/documents/:id/tokens` 본문 `engine`에 `'editor'` 값을 더한다(기존 `'libreoffice' | 'artcraft'`). `engine: 'editor'`면 서버가 **`canEdit`을 false로 강제**하고(읽기 전용 참여), 응답 `viewerUrl`을 `<editor page>?token=…&ui=view`로 준다(`editorUrlFor`의 쪽 선택 그대로: docx→editor.html, xlsx→editor-grid.html, pptx→editor-slides.html). `engine` 생략·다른 값이면 지금과 같다 — API 기본값은 바꾸지 않는다(향기랩·saturn·유지관리 시스템 영향 없음).
- `canDownload`가 false인 `engine:'editor'` 요청은 거절하지 않고 `engine:'libreoffice'` + `engineReason: '내려받기 권한이 없어 서버 변환으로 엽니다'`(아트크래프트와 같은 규칙; 편집기 자료 경로가 열람만 토큰을 거부하기 때문).
- 지원 형식: docx·xlsx·pptx(편집기가 있는 형식). .doc/.ppt/.xls는 업로드 때 변환된 저장본의 `meta.ext`가 docx/pptx/xlsx면 그대로 된다(지금 `editorUrlFor` 규칙). pdf·hwp·도면은 영향 없음.

### 3.3 메인 화면
- 각 줄에 **펼침 메뉴 없이 한 줄 단추**: **"열기"**(기본, `engine:'editor'` — docx/xlsx/pptx; pdf는 지금처럼 PDF 편집기, 그 밖(hwp·dwg 등)은 지금 `viewerUrl`) → "리브레오피스로 열기"(말풍선 "서버 변환") → "아트크래프트로 열기"(지원 형식만, 아니면 흐림 + 이유 말풍선) → "동시편집 열기"(pdf는 "PDF 편집") → "삭제". 단추 글자·동작은 예전 그대로(e2e가 글자로 찾는다).
- 목록 위 "아트크래프트와 나란히 비교해서 열기" 체크박스(03516d7)는 그대로 — 켜면 "열기"가 compare.html로.
- 공유 링크 폼의 엔진 라디오에 "읽기 전용 편집기 화면(기본)"을 더하고 기본 선택으로 둔다. "동시편집" 체크를 켜면 라디오는 비활성(편집 토큰은 편집기 그대로).
- "편집 열기" 단추(보기 꾸밈 제목 줄 오른쪽 끝): 메인 화면이 연 경우에만 보인다 — 메인 화면은 `engine:'editor'` 토큰과 함께 `canEdit=true` 토큰을 하나 더 발급해 주소를 `#edit=<editorUrl>`처럼 넘기지 않고, **단추를 누를 때** `/api/documents/:id/tokens`를 다시 불러 편집기로 이동한다(`sessionStorage`에 문서 id 보관, 업로더 본인 화면이라 API 키 규칙은 지금 메인 화면과 같음). 공유 링크로 연 사람에게는 단추가 없다.

### 3.4 그대로 두는 것
- 편집기의 그리기·배치·찾기·확대·참석자·메모 창·섬네일·워터마크·백스테이지 내려받기/인쇄 로직 — 보기 꾸밈도 같은 단추를 그대로 쓴다.
- Yjs 방 참여(읽기 전용) — 다른 사람의 편집이 실시간으로 보인다. 큰 엑셀의 방 정원(edit.ts:84)에 걸리면 `4429` → 화면은 "지금은 보는 사람이 많습니다. 서버 변환으로 보여 줍니다" 안내 뒤 같은 토큰의 보기 화면(리브레오피스 경로)으로 **자동 이동**(토큰 재발급 없이: 편집기는 `/api/view/info`의 `info.viewerUrl` — 같은 토큰의 보기 화면 주소 — 로 간다). 토큰 발급 응답의 `fallbackUrl`(같은 주소)은 API 호출 측을 위해 그대로 준다.

## 4. 검사
- 단위: `engineFor('editor')` 판정(형식·canDownload·canEdit 강제), `viewerUrl` 모양, `fallbackUrl`; `viewControlAllowed`(보기 조작 허용 목록, 복사 권한), `blockedViewKey`, `isViewUi`, `capacityFallback`.
- 브라우저 e2e(`scripts/verify-readonly-editor-e2e.mjs`, 임시 포트): docx·xlsx·pptx 각각 (1) 리본 탭(6개 이상)·판·빠른 실행·수식 입력줄이 보이고 얇은 줄은 없음, 쓰는 조작(편집기마다 11개)은 `disabled`·`aria-disabled`·`.ro-disabled`, 보기 조작(확대·찾기·메모 표시·복사·미리 보기)은 그대로, 편집 탭을 눌러 둘러보면 판이 열리고 그 안 쓰는 단추는 모두 흐림 (2) 흐린 단추 강제 클릭·타자·Delete·F2·붙여넣기·Ctrl+S/H/B/D/M/I/U·시트 탭 우클릭·이름 바꾸기 더블클릭·시트 추가(보이되 흐림)·슬라이드 끌기 — 모두 문서가 바뀌지 않음(화면 그대로, 새로 연 화면 그대로) (3) 찾기(바꾸기는 흐림)·보기 탭 확대·검토 메모 창·시트 탭 바꾸기·섬네일 이동·파일 화면(정보 "읽기 전용"·인쇄·내려받기) (4) `canCopy=false`면 복사·우클릭·선택 막힘 (5) 다른 탭의 편집이 실시간 반영, 큰 엑셀 지연 행의 조건부 서식 (6) 메인 화면 기본 "열기"가 이 화면으로(+ 편집 열기 → 편집기), 한 줄 단추 다섯 개와 각각의 화면, pdf 줄, 공유 폼 기본값, 공유 링크엔 편집 열기 없음 (7) 600px 폭(편집 열기까지 있는 제목 줄 — 가로 넘침·겹침 없음) (8) 큰 엑셀 정원 초과 → 안내 + 자동 이동 (9) 기존 e2e(verify:docx·pptx·xlsx:browser·view-only·artcraft) 그대로 통과.

## 5. 하지 않는 것
- Yjs 없이 스냅샷만 보여 주는 가벼운 모드(열기 속도 개선) — 나중에 필요하면 별도.
- 향기랩 화면 변경(늘 편집 모드 유지).
- API 기본값 변경.

## 6. 결정 기록
- 읽기 전용은 "토큰 canEdit=false(서버가 편집을 버림)" + "화면 ui=view(쓰는 도구 비활성화)" 두 겹으로 — 화면만 막으면 요청 조작으로 편집이 가능하기 때문.
- (폐기) 리본 전체를 숨기고 얇은 줄을 둔다 — 첫 안. 사용자가 실제 화면을 보고 "메뉴들이 다 너무 이상해짐"이라 하여 2026-11-21 밤에 **리본은 그대로 보이고 쓰는 조작만 비활성화**로 바꿨다. 얇은 줄(`.view-strip`)·`setViewNav`·얇은 줄 "메모" 단추는 지웠다(메모 창은 검토 → 메모 표시로).
- 메인 화면의 "▾ 다른 방식" 펼침 메뉴도 같은 결정으로 한 줄 단추로 되돌렸다.
