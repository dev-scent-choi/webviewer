# 엑셀 편집기: 원본 파일의 수식은 다시 계산되지 않음 (미해결)

- 기록일: 2026-10-27
- 상태: **미해결 — 작업하지 않기로 함(사용자 결정, 기록만)**
- 영향: 향기랩 문서 도구(docs.hyanggilab.com)와 8000의 엑셀 동시편집 화면

## 증상

| 상황 | 결과 |
|---|---|
| 원본 파일을 열었을 때 보이는 값 | **정확함** — 엑셀이 저장해 둔 계산 결과를 그대로 보여 줌(아래 32개 수식 모두 일치) |
| 편집기에서 입력 칸을 바꿈(예: F1 10 → 100) | 원본에 있던 수식은 **값이 그대로**(예: `=SUM(F1:F5)`가 150 → 240이어야 하는데 150 유지) |
| 편집기에서 수식을 새로 입력(`=SUM(A1:A3)`) | **제대로 다시 계산됨**(60 → 150) |
| 원본 수식 칸을 고르면 수식 입력줄 | `=SUM(...)` 대신 **결과값만** 보임 |

확인한 수식(열 때는 32개 모두 맞고, 입력을 바꾼 뒤 값이 달라져야 하는 18개는 그대로였다):
SUM, AVERAGE, MAX·MIN, COUNT·COUNTA, IF, IFS, SUMIF, COUNTIF, SUMIFS, COUNTIFS, AVERAGEIF, VLOOKUP,
INDEX/MATCH, XLOOKUP, SUMPRODUCT, ROUND, ROUNDUP·ROUNDDOWN, INT·MOD·ABS, TEXT, & 잇기, CONCATENATE,
TEXTJOIN, LEFT·MID·RIGHT, LEN·TRIM·UPPER, SUBSTITUTE, IFERROR, ISBLANK·ISNUMBER, AND·OR·NOT,
YEAR·MONTH·DAY, 다른 시트 참조, RANK, MAXIFS.

## 원인

원본 xlsx를 읽을 때(`src/spreadsheet.ts` `displayValue`, 대용량은 `src/xlsx/lazyGridStore.ts` `ingestXlsxLazily`),
엑셀이 캐시해 둔 결과가 있는 수식 칸은 **수식 원문이 아니라 결과값만** 칸 값으로 저장한다(결과 캐시가 없을 때만
`=수식` 원문을 남긴다). 서버의 재계산(`src/collab/room.ts` `recomputeFormulasForPage`)은 칸 값이 `=`로 시작하는
칸만 수식으로 보므로, 원본 수식 칸은 보통 값 칸으로 취급되어 다시 계산되지 않는다.

## 저장에 미치는 영향

- 저장은 편집한 칸만 원본에 반영하므로 원본 수식 자체는 파일에 그대로 남는다.
- 다만 그 수식 칸에 캐시된 결과는 예전 값이다. 엑셀로 다시 열 때 다시 계산되는지는 확인하지 않았다.

## 고친다면 (작업 메모 — 설계 아님)

1. 원본을 읽을 때 수식 칸의 **수식 원문도 함께** 보관한다(결과값은 화면 표시용으로 유지).
2. 재계산이 그 수식 원문을 보고 계산하게 하고, 수식 입력줄에는 원문을 보여 준다.
3. 계산 엔진(fast-formula-parser)이 모르는 함수거나 계산에 실패하면 **엑셀이 저장해 둔 값을 그대로** 보여 준다
   (지금보다 나빠지지 않게).
4. 수식이 아주 많은 대용량 파일에서 편집할 때 계산 시간이 늘지 않는지 따로 시험한다.
5. 검증: 위 32개 수식 표(열 때 + 입력 변경 뒤)를 회귀 시험으로 남기고, `npm run verify:xlsx`·대용량 xlsx 시험을 통과시킨다.

관련: 같은 날 고친 HYPERLINK 수식 링크(`IFERROR(HYPERLINK("#'"&$A2&"'!a1",…))`)는 이 문제와 별개로 동작한다 —
링크 주소는 누를 때 편집 화면이 지금 칸 값으로 따로 계산한다(`src/client/gridLinks.ts` `evalLinkExpr`).
